# Data

costlens ships one dataset. It is synthetic, and it is generated by the code in this
repository. No external datasets are downloaded.

## `examples/demo-cluster/` (about 5.5 MB, committed)

| item | value |
| --- | --- |
| Source | `costlens generate --out examples/demo-cluster --weeks 6 --step 15m --seed 7` (also `make fixture`) |
| Generator | `src/costlens/synth/` (spec in `spec.py`, simulation in `generator.py`) |
| License | MIT, same as the project (generated by project code) |
| Period | 2026-03-02T00:00Z to 2026-04-13T00:00Z (42 days), 4032 steps of 900 s |
| Cluster | 7 nodes in 3 pools (general m5.2xlarge ×3, memory r5.xlarge ×2, spot batch c5.2xlarge ×1, +1 from day 9.5), 9 namespaces, 17 workloads, 495 containers over the period |
| Format | Prometheus `/api/v1/query_range` responses, gzip, one file per metric per week, plus `manifest.json` |
| Reproducibility | `tests/test_fixture.py` regenerates it and compares (tolerances absorb cross-CPU libm ulps) |

The directory also contains three files that a real export would not have:

- `pricing.toml` is the pricing catalog the simulated nodes were billed from. The prices are
  **illustrative approximations** of public on-demand list prices (m5.2xlarge $0.384/h,
  r5.xlarge $0.252/h, c5.2xlarge $0.34/h); the spot price ($0.119/h) is a synthetic 65%
  discount. They are not quotes, so verify against your provider before relying on them.
- `ground_truth.json` holds per-tenant costs for 9 allocation scenarios, computed directly
  from the simulation by `synth/truth.py`. It is used by the tests and by `make eval`.
- `true_cpu_demand_cores.*.json.gz` and `true_memory_demand_bytes.*.json.gz` hold uncensored
  demand, listed under `manifest.extra.truth_files`. The backtest uses them for its
  "simulation only" table.

What the simulation models:

- diurnal and weekend seasonality, plus slow weekly growth
- lognormal CPU noise and CPU spikes
- Deployment rollouts, CronJob runs and DaemonSets
- one sidecar per pod in two workloads
- an unlabelled namespace, and a pod-level team label override
- a leaking container that is OOM-killed at its memory limit
- limits that censor observed usage
- a spot pool, and a node that joins mid-period

What it does not model:

- real application behaviour or correlated incidents
- node failures and evictions
- autoscalers (HPA, VPA, cluster autoscaler)
- network, storage and GPU costs

## Test data

The tests generate their own small clusters, for example two weeks at a 1-hour step with
seed 11, into pytest temporary directories, and build hand-made `ClusterDataset`s in memory.
Nothing is downloaded.
